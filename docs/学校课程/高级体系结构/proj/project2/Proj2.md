## 作业描述

本次作业对 `maca-transpose` 进行 GPU kernel 优化，在保持接口和转置结果正确的
前提下，提高 MACA 平台上的访存与并行执行效率。

工程目录为 `Lab2/program/`，主要实现位于 `kernel.cpp`。矩阵转置的复杂度仍为
`O(m × n)`，优化重点是**合并全局读写、均衡共享内存 bank 访问，以及减少访存指令开销**。

## 实践

### 项目解析

- `main.cpp`：申请设备内存、传入矩阵，重复执行 10 次，通过 GPU event 记录耗时。
- `kernel.h`：暴露 `macaTranspose(input, output, m, n)`；输入为行优先存储的
  `n` 行 `m` 列矩阵，输出为 `m` 行 `n` 列，两个缓冲区不得重叠。
- `kernel.cpp`：指针满足向量对齐时选择 V2，否则使用标量 V1；入口只异步提交
  一个 kernel，不增加设备内存分配、同步或运行时调优。

题目要求边长为 64 倍数的方阵，但驱动程序默认使用 `n × 2n` 的矩形。
实现兼容两者，要求正尺寸 `m`、`n` 均为 64 的倍数。

#### kernel.cpp：矩阵转置与访存优化

##### 1. 原始瓶颈：读连续，写跨行

转置关系为：

```cpp
output[c * n + r] = input[r * m + c];
```

原实现由相邻线程处理相邻输入列 `c`，因此读取连续；但输出地址相差 `n` 个
float，写入分散。按 128 字节缓存行分析，32 个线程的一轮标量写入触及
32 条缓存行，每条仅写一个 float，无法充分利用访存带宽。

解决办法是先连续读入共享内存，再以转置后的线程映射连续写出，将跨线程的数据
交换放到片上完成。这里的共享内存用于**重排数据**，每个元素仍只读写各一次。

##### 2. V1：共享内存分块与 padding

V1 使用 `32 × 8 = 256` 个线程处理一个 `32 × 32` tile，每线程负责 4 个元素：

```cpp
__shared__ float tile[32][33];
// offset = 0, 8, 16, 24；全局地址分别使用输入块、转置输出块的坐标。
tile[ty + offset][tx] = input[...];
__syncthreads();
output[...] = tile[tx][ty + offset];
```

两侧全局访问均沿连续列展开。若共享数组为 `[32][32]`，按列读取时地址间隔为
32 个 float，会集中到同一 bank；增加一列后，在 32 个四字节 bank 的模型下：

```text
bank = (tx + ty + offset) % 32
```

每组 32 线程覆盖所有 bank，避免按列读取的集中冲突。该路径使用 **4224 字节**
共享内存，也用于处理不满足 `float4` 对齐条件的指针。

##### 3. V2：64×64 分块与双向向量化 IO

V2 保持原版每块处理 `64 × 64` 个元素，线程布局改为 `16 × 16`。
每线程处理 4 行，每行一个 `float4`，共 16 个元素：

```text
输入 tile 坐标：r = ty + 16*i，c = 4*tx + s
转置读取坐标：tile[4*tx + s][ty + 16*i]
i、s ∈ [0,3]
```

写回时交换块坐标，并将行跨度由 `m` 改为 `n`，实现矩形矩阵的正确转置。

| 每个 64×64 输入块 | 原版 | V2 |
| --- | ---: | ---: |
| 线程数 | 1024 | 256 |
| 每线程元素数 | 4 | 16 |
| 全局加载操作数（源码层面） | 4096 次标量 | 1024 次 float4 |
| 全局存储操作数（源码层面） | 4096 次标量 | 1024 次 float4 |

在基址按 128 字节对齐时，每组 16 线程连续访问 256 字节，恰好覆盖两个完整
缓存行。向量化减少访存指令与地址处理开销，线程内多元素处理则提高单线程工作量；
两者都不改变每块元素数或 kernel 启动次数，也不意味着运行时间必然缩短为四分之一。

##### 4. 共享内存位重排：适配 float4 的线程映射

向量布局中，同一标量分量对应的列间距为 4；直接使用 `[64][65]` 的 padding，
仍会在每组 32 线程内形成 2 路 bank 冲突。V2 改用无填充的 `[64][64]` 数组，
将逻辑列 `c` 映射到物理列：

```cpp
p(r, c) = ((c & 2) << 4)
        | (((c >> 2) ^ (r >> 2)) << 1)
        | ((r ^ c) & 1);
```

固定行时，该映射是 64 列的可逆排列，不会覆盖数据。对应 bank 为：

```text
bank(r,c) = 2*((r >> 2) ^ (c >> 2)) + ((r ^ c) & 1)
```

无论协作写入还是转置读取，连续 32 线程都包含两个相邻的 `ty`：一行遍历
16 个偶数 bank，另一行遍历 16 个奇数 bank，合起来每个 bank 恰好访问一次。
对 64 线程 wave，则是每个 bank 两个字的均衡需求，达到 32 个单字宽 bank
服务 64 次标量请求所需的最低轮数。

因此，V2 同时保持全局向量读写与共享访问均衡，且只需 **16 KiB** 共享内存和
一次块级屏障。全局访问使用 `float4`，共享内存重排仍使用标量访问。

##### 5. 循环展开、ILP 与地址计算

- **分阶段暂存**：先将四个独立 `float4` 载入寄存器，再写共享内存；同步后先
  收集四个输出向量，再写全局内存，增加可并行调度的访存指令，帮助隐藏延迟。
- **固定循环展开**：`#pragma unroll` 请求展开 4 轮加载、重排和输出，减少循环
  控制开销，并为跨迭代调度提供条件。
- **地址预计算**：每线程只计算一次输入、输出基址，后续访问使用常量倍数步长；
  全局偏移采用 `std::size_t`，避免 32 位乘积溢出。
- **编译器约束**：`__restrict__` 声明缓冲区不重叠，`__forceinline__` 请求内联
  映射函数，`__launch_bounds__(256)` 声明线程块上限。寄存器暂存也会增加资源占用，
  实际收益取决于编译结果与驻留率。

##### 6. 正确性与性能边界

尺寸整除使网格 `(m/64, n/64)` 中每个 tile 都完整，无需逐元素边界判断。
共享映射可逆，所有线程均参与屏障，每个输出只有一个写入者；纯数据搬运不涉及
浮点累加或精度替换。入口检查向量对齐，不满足时回退 V1；非正尺寸不启动 kernel。

每个元素只进行一次全局读取和一次写入，逻辑数据流量为 **`8*m*n` 字节**。
性能提升主要来自减少分散写入、改善 bank 分布，以及降低指令开销；实际显存事务、
缓存命中与带宽利用率仍取决于硬件和编译器。
