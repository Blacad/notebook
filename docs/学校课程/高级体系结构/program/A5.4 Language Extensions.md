## C/C++ Language Extensions（C/C++ 语言扩展）

### 函数执行空间限定符（Function Execution Space Specifiers）

- `__global__`：内核函数，在 device 上执行；返回类型必须为 ==void==；调用是异步的；可从 host 调用（在支持动态并行的设备上也可从 device 调用）
- `__device__`：仅在 device 上执行，只能从 device 调用；==不能与 `__global__` 一起用==
- `__host__`：仅在 host 上执行，只能从 host 调用；等价于不加限定符；==不能与 `__global__` 一起用==(不加空间限定符的函数默认为`__host__`)
- `__host__ __device__`：同时为 host 和 device 编译，可用 `__CUDA_ARCH__` 宏区分两条代码路径
- `__noinline__` / `__forceinline__`：提示编译器避免/强制内联 `__device__` 函数；二者==不能同时使用==
- 交叉执行空间的非法调用（如定义了 `__CUDA_ARCH__` 时从 device 调 `__host__` 函数）会导致未定义行为

- ==调用说明==
	-  "从 host 调用" = CPU 代码发起调用 `__host__`
	- "从 device 调用" = GPU 代码（kernel 内部）发起调用  `__device__` or `__global__`

### 变量内存空间限定符（Variable Memory Space Specifiers）

| 限定符 | 位置 | 可访问者 | 生命周期 |
| --- | --- | --- | --- |
| `__device__` | 设备/全局内存 | 所有网格线程 + host（通过 Runtime API） | 程序 / CUDA 上下文 |
| `__constant__` | 常量内存（device 上只读） | 所有网格线程 + host | 程序 / CUDA 上下文 |
| `__managed__` | 统一内存（host + device） | host 与 device 线程 | 程序 |
| `__shared__` | 片上共享内存（每 SM） | 同块线程 | 块 |
| （无） | 寄存器（或局部内存） | 单线程 | 单线程 |

- `__device__` / `__constant__` 变量可从 host 通过 `cudaGetSymbolAddress()`、`cudaGetSymbolSize()`、`cudaMemcpyToSymbol()`、`cudaMemcpyFromSymbol()` 访问
- `__shared__` 可有静态大小（编译期确定）或动态大小（启动时确定）
	- 动态共享变量须声明为外部数组或指针；静态共享变量==不能在声明时初始化==
- `__managed__` 变量的限制：地址不是常量表达式、不能是引用类型、不能在 CUDA runtime 无效状态下使用（如静态/动态初始化或析构）
- `__grid_constant__`（计算能力 7.0+）：标注 const 限定的、非引用的 `__global__` 函数参数；这些参数具有网格生命周期、网格私有、只读，==避免每线程拷贝==以提升性能
- `__tile__`：类似 `__device__`，但直接从 tile 代码（而非 SIMT 代码）访问

### 内建向量类型（Built-in Vector Types）

- CUDA 提供由基本整型/浮点型派生的向量类型，host 与 device 均可用
- 分量通过字段 `x`、`y`、`z`、`w` 访问；构造用 `make_<类型名>`（如 `make_int2(x, y)`）
- 类型：`char1-4`、`uchar1-4`、`short1-4`、`ushort1-4`、`int1-4`、`uint1-4`、`long1-4`、`ulong1-4`、`longlong1-4`、`ulonglong1-4`、`float1-4`、`double1-4`
- 对齐要求因类型而异（如 `int4` / `uint4` / `float4` 为 16 字节对齐；`char3` / `uchar3` 为 1 字节对齐）
- `dim3`：基于 `uint3` 的整型向量类型，用于指定维度；未指定分量默认为 1（C++11 及以后）

### 内建变量（Built-in Variables）

- 仅 device 端有效（tile 代码中不支持）：
	- `dim3 gridDim`：网格维度（x/y/z 各方向的块数）
	- `dim3 blockDim`：线程块维度（x/y/z 各方向的线程数）
	- `uint3 blockIdx`：网格中的块索引
	- `uint3 threadIdx`：块内的线程索引
	- `int warpSize`：一个 warp 的线程数（通常为 32）
- 这些内建变量仅在 device 上执行的函数内有效

### 内存栅栏函数（Memory Fence Functions）

- CUDA 采用==弱序内存模型（weakly-ordered memory model）==：写操作被观察到的顺序可能与程序顺序不同
- 栅栏函数只对==调用线程==的内存访问排序，本身不保证对其他线程可见（可见性由同步函数如 `__syncthreads` 提供）
	- `__threadfence_block()`：确保调用线程的全局/共享内存访问对==同块内所有线程==可见
	- `__threadfence()`：全局内存访问对==设备上所有线程==可见；共享内存访问对同块内所有线程可见
	- `__threadfence_system()`：额外保证对==页锁定主机内存（page-locked host memory）==的访问对 host 线程可见

### 同步函数（Synchronization Functions）

- `void __syncthreads()`：块级栅栏 + 块内存栅栏；等待块内所有线程到达，并确保块内线程的全局/共享内存访问可见
- `int __syncthreads_count(int predicate)`：返回块内 `predicate != 0` 的线程数
- `int __syncthreads_and(int predicate)`：当且仅当块内==所有==线程 `predicate != 0` 时返回非零
- `int __syncthreads_or(int predicate)`：当且仅当块内==任一==线程 `predicate != 0` 时返回非零
- `void __syncwarp(unsigned mask = FULL_MASK)`：warp 级栅栏，只同步指定的 lane；仅活跃线程需要到达；提供 warp 范围的同步与内存栅栏
- 使用约束：
	- `__syncthreads()` 只同步==同一块内==的线程；不同块的线程无法直接同步
	- 在条件语句中使用时，须保证块内==所有线程==到达同一调用点，否则可能死锁或未定义行为
	- Volta 起独立线程调度后，warp 内线程不再默认锁步执行；通过共享/全局内存交换数据的代码须插入 `__syncwarp()`

### Warp 级内建函数（Warp Intrinsics）

- CUDA 9 起引入带 `*_sync` 后缀的 warp 内建函数，显式传入参与 lane 的掩码；无后缀形式已弃用并移除
- 洗牌（shuffle）：
	- `T __shfl_sync(unsigned mask, T var, int srcLane, int width = warpSize)`：获取同 warp 内另一 lane 的值（同一 `srcLane` 为广播，不同 `srcLane` 为置换）
	- `__shfl_up_sync` / `__shfl_down_sync` / `__shfl_xor_sync`：分别获取较低/较高 lane 的值、`lane XOR mask` 处的值
- 投票（vote）：
	- `uint __ballot_sync(unsigned mask, int predicate)`：返回位掩码，第 i 位对应第 i 个线程的 predicate
	- `int __all_sync(unsigned mask, int predicate)`：mask 内所有活跃线程 predicate 都非零则返回非零
	- `int __any_sync(unsigned mask, int predicate)`：mask 内任一活跃线程 predicate 非零则返回非零
	- `uint __activemask()`：返回 warp 内活跃线程的位掩码
- warp shuffle 广泛用于归约、前缀和、FFT 等；相比共享内存，延迟更低、无需 `__syncthreads`、无 bank 冲突、纯寄存器通信，但仅限于单个 warp

	```c++
	// warp 内典型归约
	for (int offset = warpSize/2; offset > 0; offset /= 2)
	    mySum += __shfl_down_sync(FULL_MASK, mySum, offset);
	```

### 只读数据缓存加载（Read-Only Data Cache Load）

- `__ldg()`：通过只读数据缓存（read-only data cache）加载数据，适合只读访问，可提升带宽利用率
- Kepler 及之后，用 `const __restrict__` 指针也能让编译器自动走只读缓存

### 执行配置与启动边界（Execution Configuration）

- `<<<gridDim, blockDim, sharedMemSize, stream>>>` 三箭头语法指定内核启动的执行配置
	- 前两个参数分别是网格维度与线程块维度，可用 `dim3` 或整数
	- 可选参数：动态共享内存字节数、关联的 CUDA stream
- `__launch_bounds__(maxThreadsPerBlock, minBlocksPerMultiprocessor)`：限定每块最大线程数（及每 SM 最小块数），用于优化内核的寄存器使用/占用率

### 其他扩展（Other Extensions）

- 数学函数（Mathematical Functions）：大量 device 数学函数（如 `__sinf`、`__expf` 等快速内建版本）
- 纹理函数（Texture Functions）：`tex1Dfetch`、`tex2D` 等
- 原子函数（Atomic Functions）：`atomicAdd` 等（详见《Writing CUDA SIMT Kernels》笔记）
- 时间函数：`clock()`、`clock64()`
- 格式化输出：`printf`（device 端）
- 动态全局内存分配：`malloc` / `free`（device 端）
- 断言与陷阱：`assert`、`__trap()`、`__brkpt()`
- `#pragma unroll`：提示编译器展开循环
