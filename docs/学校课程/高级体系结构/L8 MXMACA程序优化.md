

> [!summary] 核心思路
> **先判断瓶颈，再调整并行粒度、减少线程束分化、提高数据复用；线程越多或占用率越高，不代表程序一定越快。**

## 一、并行执行层次（P2–4、P16）

- **Host**：CPU 及主存，负责控制流程、发起 Kernel；**Device**：GPU 及显存，负责并行计算，二者经 PCIe 连接。
- **Thread → Block → Grid**：线程是最小计算单元；块内线程共享 shared memory；Grid 由多个 Block 组成，使用 global memory。
- **Wave**：硬件 SIMD 执行的线程束。同一 Wave 的线程共同执行指令，因此控制流是否一致会影响效率。

## 二、调整线程粒度与占用率（P5–6）

### 1. 线程粗化（Thread Coarsening）

**让一个线程处理多个数据元素，减少完成同一任务所需的线程数。**

- 例：向量加法由“每线程处理 1 个元素”改为“每线程处理 4 个元素”。
- 目的：减少调度、同步等开销，更充分地利用计算资源。
- 权衡：每线程工作量及资源需求可能增加；粗化过度会减少并行度，所以应通过实测选择粗化因子。

### 2. 选择 Block / Grid 大小

- **Occupancy（占用率）**：一个 AP 上实际驻留的活跃 Wave 数与硬件允许的最大驻留 Wave 数之比。
- Block 大小、每线程寄存器用量、每块共享内存用量等，会限制可同时驻留的线程块和 Wave 数。
- `mcOccupancyMaxPotentialBlockSize`：可用于获取有利于提高占用率的 Block 大小建议；相关 API 见 `/opt/maca/include/mcr/mc_runtime_api.h`。
- **高占用率有助于隐藏延迟，但不是最终目标**；仍需结合执行时间、访存效率和资源使用情况判断。

## 三、减少线程束分化（P7–8）

**线程束分化（Wave Divergence）**：同一 Wave 内的线程走不同分支或执行不同次数的循环。

- **分支分化**：不同路径通常分时执行，暂不执行该路径的线程被屏蔽，降低有效执行比例。
- **循环分化**：若各线程的循环上界不同，先完成的线程会闲置，直到最晚完成的线程退出。
- 课件例：`N = a[threadIdx.x]`，各线程执行 `for (i = 0; i < N; ++i)`；循环次数不一致也会分化，**不只是 `if/else` 才会分化**。
- 优化方向：尽量让同一 Wave 的控制流、任务量接近；必要时将相似任务分组处理。

> [!tip] 判断范围
> 关键是**同一 Wave 内**是否分化，而不是整个 Grid 的所有线程是否执行完全相同的任务。

## 四、利用内存层次（P9–11、P15）

越靠近计算单元，存储通常越小、越快、每字节成本越高。课件强调 GPU 相比 CPU **带宽更高、延迟更大、缓存更少**，需要通过并行与数据复用提升效率。

| 存储类型 | 作用范围 | 优化要点 |
| --- | --- | --- |
| 寄存器 | 单个线程 | 片上、最快，但资源有限 |
| 私有内存 | 单个线程 | 位于片外，不能因“私有”就认为很快 |
| 共享内存 | 同一 Block | 片上，用于块内复用；注意 Bank 冲突 |
| 全局内存 | 全部线程 | 容量大、访问较慢，尽量减少重复访问 |
| 常量内存 | 全部线程（设备端只读） | 适合只读常量数据 |

- 寄存器、私有、共享、全局、常量内存属于课件所述的**可编程存储单元**；L1 / L2 缓存主要由硬件管理。
- 优化原则：**尽可能在寄存器或共享内存中复用数据，减少片外数据搬运**。

## 五、Roofline 模型：判断性能上限（P12–13）

### 1. 算术密度与性能上限

$$
AI = \frac{\text{浮点运算次数（FLOP）}}{\text{数据传输字节数（Byte）}}
$$

$$
P \le P_{\mathrm{roof}} = \min\left(P_{\mathrm{peak}},\ AI \times B_{\mathrm{peak}}\right)
$$

- $AI$：算术密度，也称计算访存比，单位 FLOP/Byte。
- $P_{\mathrm{peak}}$：峰值计算吞吐率；$B_{\mathrm{peak}}$：峰值内存带宽。
- 图中横轴为 $AI$，纵轴为可达到的计算吞吐率；双对数坐标下，屋顶由**带宽斜线 + 算力水平线**组成。

### 2. 瓶颈与优化方向

拐点对应硬件的**算力带宽比**：

$$
AI_{\mathrm{balance}} = \frac{P_{\mathrm{peak}}}{B_{\mathrm{peak}}}
$$

| 条件                           | 屋顶所反映的限制              | 主要优化方向             |
| ---------------------------- | --------------------- | ------------------ |
| $AI < AI_{\mathrm{balance}}$ | 带宽受限（Bandwidth-bound） | 减少数据搬运、提高数据复用和有效带宽 |
| $AI > AI_{\mathrm{balance}}$ | 算力受限（Compute-bound）   | 提高有效计算吞吐，减少分化和执行空闲 |

> [!important] 上限不等于实测性能
> Roofline 给出理论上限。即使算术密度高，程序也可能因并行度不足、分化或延迟未被隐藏而远低于屋顶，不能只看 $AI$ 就断定实际瓶颈。

## 六、另外两个性能模型（P14）

### 1. Amdahl 定律：串行部分限制加速比

课件以 Amdahl 定律说明固定问题规模下的扩展性：

$$
S_p \le \frac{1}{(1-f)+f/p}, \qquad
S_{p\to\infty} \le \frac{1}{1-f}
$$

$f$ 为可并行部分的比例，$p$ 为并行处理单元数。**只增加 GPU 并行资源，无法消除串行部分造成的性能上限。**

### 2. Little 定律：足够并发才能隐藏延迟

将课件中的吞吐关系写为：

$$
R = \min\left(R_{\max},\frac{N}{L}\right)
$$

$N$ 为并发任务或请求数，$L$ 为平均延迟，$R_{\max}$ 为吞吐上限。要达到目标吞吐率，需有约 $N \ge R L$ 的并发量。

**启示：GPU 需要足够多的独立工作来隐藏访存延迟；增加并发只能提升到硬件吞吐上限。**

## 复习速记

- **线程粗化**：每线程多做事，减少开销，但要防止并行度下降。
- **Occupancy**：帮助隐藏延迟，不等于实际性能。
- **Wave 分化**：分支不同、循环次数不同，都可能浪费执行通道。
- **Roofline** 看算力与带宽上限；**Amdahl** 看串行比例；**Little** 看并发是否足够。
