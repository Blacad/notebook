- 大模型处理文本的过程
	- messages(对话消息) -> template(增添特殊token后的结构性文本) -> tokenizer(input_ids\attention_mask\...) -> model -> decode -> token(str)
	- `messages=[{"role":"system","content":"..."},{...},...]`
	- `tokenizer.apply_chat_template(messages, tokenize=False,add_generation_prompt=True)` -> format text(str)
		- 这里将 tokenize 置为 False 则是只转换为 结构化文本 而不进一步变为BatchEncoding，常规直接为 True 就好，就等同于 先进行 template 再进行 tokenizer
	- `tokenizer(text, return_tensors="pt")` -> BatchEncoding 对象继承于字典，有input_ids\attention_mask 等 key
		- `return_tensors`
			- `pt` 指明返回的 pytorch tensor
			- `tf` 指明返回的 tensorflow tensor
			- `np` 指明返回的 NumPy 数组
			- `None` (默认)时，返回 Python 列表
	- `model(**inputs)` -> outputs(CausalLMOutputWithPast对象)
		- `outputs.logits` 就是模型一次 forward 后的完整输出结果

	- `tokenizer.decode([torch.argmax(outputs.logits[:,-1,:]), dim=-1).item()],skip_special_tokens=True)` -> 贪心解码出下一个token

- 上述处理过程只是为了详细描述模型的运行逻辑，实际上如果真实生成只需要 `model.generate()` 就好，它内部封装了完整的自回归生成流程，并支持多种解码策略（贪心、采样、束搜索等），无需手动循环和采样
	```python
	generated_ids = model.generate(
	    **inputs,
	    max_new_tokens=512,        # 最大生成 token 数
	    do_sample=True,            # 开启采样
	    temperature=0.7,           # 控制随机性，值越大越随机
	    top_p=0.9,                 # 核采样，累积概率阈值
	    top_k=50,                  # 可选：限制候选 token 数量
	    eos_token_id=tokenizer.eos_token_id,
	    pad_token_id=tokenizer.pad_token_id
	    )
	response = tokenizer.decode(generated_ids[0][inputs['input_ids'].shape[1]:], skip_special_tokens=True)
	```
