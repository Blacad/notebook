
## Intro

- 四个工具
	- DeepSpeed --- multi-GPU
	- FlashAttention --- Long context
	- Liger Kernel --- Long context
	- Quantization --- small vRAM


- 8B模型训练为例
	- 往往分成两部分，fp32 + bf/fp16，实际推理回传梯度时采用 bf/fp16，而训练更新时采用 fp32(混合精度训练Mixed Precision Training)
	- fp32 --- 32GB(weights) + 32GB(momentum) + 32GB(variance)(为了更新稳定)
	- fp16 --- 16GB(weights) + 16GB(gradients)(为了速度)
	- 16+16+32+64=128GB，这还没有算激活值，仅仅算模型及其优化器


- Activation re-computation
	- 如果把所有激活值都存下来将会非常恐怖，因此引入了 Activation re-computation 也就是 gradient checkpoint
	- 方法：在正向传播过程中保存“重要激活”，然后在反向传播时需要时重新计算（计算开销）

- Batch Size
	- 批大小应该足够大以提供清晰的梯度。通常每批4-60M个token。（DeepSeek V3使用1920的批大小进行32K上下文，即61M个token）
	- gradient accumulation
		- 全局批量大小 = 微批量大小 * 梯度累积
			- 1920 = 16 \* 120


## 模型本身

***分布式***

- DeepSpeed --- ZeRO (微软)
	- Zero-1
		- 优化器分GPU放，其他每个GPU都有
	- Zero-2
		- 优化器、梯度、32bit的参数分GPU放，16bit的参数每个GPU都有
	- Zero-3
		- 所有组件都分GPU放，需要完整计算时，通过 All-Gather 得到临时完整的层，然后不需要后就可以释放，将计算结果再 Reduce-Scatter回各自GPU，如此进行
	- Zero-Offload
		- optimizer offload
			- GPU只保留 16bit参数，其余全放在CPU
		- optimizer + model parameter offload
			- 所有组件都放在CPU上，只有计算到某处时才放进GPU计算
		- 传输速度会很慢，往往不会使用

- FSDP 和 Zero-3 很像，但是有些细微的地方不同，一般都通过 `accelerate` 作为顶层接口，然后 配置 `accelerate 的 config 文件` 就好


## Activation

***CUDA Kernel***

- Flash Attention Algorithm
	- Computation
		- 将 Attention 的计算用 ==特别设计的CUDA核函数== 完成，大大减少所需时间
	- Memory
		- 同时它还会将 CPU 和 GPU 进行协作，把存储任务部分委派给CPU，使得Memory的压力也大幅度减小


- Liger Kernel
	- 使用优化的Triton代码重新实现一些核心LLM计算
	- 用法简单
		-  `from transformers import AutoModelForCausalLM` -> `from liger_kernel.transformers import AutoLigerKernelForCausalLM`
	- 支持 LLaMA、Mistral、Gemma、Qwen、Phi 等等
