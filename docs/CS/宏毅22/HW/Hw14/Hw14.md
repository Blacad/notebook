- 说明
	- 本次作业关注于 终身学习，主要通过 Regularization-based Approach 中的 prior-focused 去实现终身学习
	- 具体任务就是将 手写数字识别 通过旋转划分成5个任务，需要通过终身学习的方式去训练模型，也就是说只能依次训练5个任务，不能一次性训练所有任务，最终按照终身学习的评估方式检测模型的能力(训练一个任务就测每个任务的得分)
	- 本次作业是知识拓展类的，不是自己设计算法，而是重在理解别人的终身学习算法

- 依旧常规pipeline
	- 数据集准备 -> 模型搭建 -> 训练器搭建 -> 推理过程
		- 训练器搭建中涉及 数据读取、优化器/损失函数设计以及学习率规划器等等环节

- 数据集准备
	- 准确来讲应该是数据集构造，通过 `transforms.Compose` 构造转换通路，通路由对图像处理的各种函数组成
		- 这里还有 `transforms.Lambda(lambda x: ....)` 其实主要是用于封装使得格式统一，也可以直接用内部函数
		- 函数默认传递参数就是 `img`
		- 填充图像 `nn.functional.pad(img, padding, padding_mode, fill)`
			- 其中 padding 是 tuple 依次指定`left, right, top, bottom` 的 padding size，当然 padding 也可以是整数相当于各个方向padding一样的值



- 模型搭建
	- 无甚可说，非常简单的MLP

- 训练器搭建
	- 最重要的就是 loss 设计，整体 loss 由 目标loss和终身学习loss两部分组成
		- `total_loss = objective(outputs, labels) + lll_lambda * lll_loss`
		- 部分 lll 方法不仅会产生额外的loss，还会直接 update 参数，因此整体的流程是
			- 记录损失 -> lll 直接update参数 -> 反向传播 -> 优化器更新参数
		- 后续依次介绍各种 终身学习 方法的 `lll_loss` 计算以及可能存在的`update`方法

	- Baseline
		- 没有 lll_loss

	- EWC(Elastic Weight Consolidation)
		- `lll_loss` 计算
			- `_loss = self._precision_matrices[n] * (p - self.p_old[n]) ** 2`
			- 前半项为 guard 矩阵(初始全部为0)
			- ==guard 矩阵的更新策略==如下
				- 当本次任务的训练结束后，我们重新将本次任务的训练数据跑一遍(eval模式)，==这里的 loss使用的 nll== 即 `F.nll_loss(F.log_softmax(output, dim=1), label)`
				- 每个batch得到的 grad 的平方/ 总batch数量 加上 之前的guard 矩阵得到新的 guard 矩阵 `precision_matrices[n].data += p.grad.data ** 2 / number_data`
				- 依次进行上述更新直到本次任务的训练数据遍历完一遍
		- 无update过程
		- 它的核心逻辑就是 参数对目标的重要性


	- MAS (Memory Aware Synapses)
		- `lll_loss` 计算
			- `_loss = self._precision_matrices[n] * (p - self.p_old[n]) ** 2`
			- 前半项为 guard 矩阵(初始全部为0)
			- ==guard 矩阵的更新策略==如下
				- 当本次任务的训练结束后，我们重新将本次任务的训练数据跑一遍(eval模式)，==这里的 loss使用的 l2_norm== 即 `l2_norm = output.norm(2, dim=1).pow(2).mean()`
				- 每个batch得到的 grad 的平方/ 总batch数量 加上 之前的guard 矩阵得到新的 guard 矩阵 `precision_matrices[n].data += p.grad.data ** 2 / number_data`
				- 依次进行上述更新直到本次任务的训练数据遍历完一遍
			- 无update过程
			- 相比 EWC，就是将 loss 更改为了 l2_norm 因此不需要 label
			- 它的核心逻辑就是 参数对输出的重要性

	- SI(Synaptic Intelligence)
		- ==将部分需长久保存的数据记录在模型中==
			- `self.model.register_buffer('{}_SI_prev_task'.format(n), p_current)`
			- buffer 不会出现在 `model.parameters()` 中不需要梯度更新，但需要跟着模型一起保存和移动，因此 buffer 的定位就是 **不参与梯度优化、但属于模型状态的 Tensor**
			- 例如 BatchNorm 里的 `running_mean`、`running_var` 也是典型的 buffer
		- `lll_loss` 计算
			- `_loss = omega * (p - prev_values) ** 2`
				- 前半项 `omega` 是 SI 中每个参数的重要性矩阵
				- `prev_values` 是上一个任务训练结束时保存的参数值
			- omega的更新过程
				- `p_change = p_current - p_prev` -> `omega_add = W / (p_change ** 2 + epsilon)` -> `omega_new = omega + omega_add` 即： $\Omega_i^{old} + \frac{W_i}{(\theta_i^{current}-\theta_i^{prev})^2+\epsilon}$ 
				- 分母使用任务开始到任务结束的**总参数变化平方**，避免单纯因为某个参数移动距离很大，就把它错误地认为非常重要
				- `epsilon` 用于防止参数变化非常小时除零，同时避免 `omega` 变得异常大
				- 新任务开始后，使用累计得到的 `omega` 对重要参数施加二次惩罚：  
						`omega * (p - prev_values) ** 2`
		- update过程
			- `self.W[n].add_(-p.grad * (p.detach() - self.p_old[n]))`
			- 每次正常训练(外层任务训练)得到梯度后调用 `update()`：
				- `W[n].add_(-p.grad * (p.detach() - p_old[n]))`
					- 其中：
						- `p.grad` 是当前 step 的 loss 对参数的梯度
						- `p - p_old` 是这一步 optimizer 更新造成的参数变化
						- 因此每一步累计：  
							$W_i \leftarrow W_i-g_i\Delta\theta_i$
				- `p_old[n]` 每个 step 都会更新成当前参数：  
					`p_old[n] = p.detach().clone()`
				- 所以 `W` 累积的是**整个任务训练过程中，每个参数的变化对 loss 改善所做的贡献** --- `grad` 反应参数变化多陡，`(p.detach() - self.p_old[n])` 反应参数实际走了多少，二者结合就是 该参数的变化对loss的贡献

	- RWalk(Remanian Walk for Incremental Learning)
		- `lll_loss` 计算
			- `_loss = (omega + self._precision_matrices[n]) * (p - prev_values) ** 2`
				- 前半项 `omega` 和 `self._precision_matrices[n]` 共同组成 `guard` 矩阵
				- 其中 `omega` 计算过程上与 SI 一致，但是计算 `omega_add` 和 `omega_new` 的公式有所不同
					- `p_change = p_current - p_prev` -> `omega_add = W / (1.0 / 2.0*self._precision_matrices[n] *p_change**2 + self.epsilon)` -> `omega_new = 0.5 * omega + 0.5 *omega_add`
				- `self._precision_matrices[n]`  计算过程上与 EWC 大体一致，但是在前面增添了更新
					- 更新->`precision_matrices[n].data *= (1 - self.update_ewc_parameter)` 
					- 与原EWC完全一致的重新跑训练任务得到梯度，但是 更新矩阵的公式变为 `precision_matrices[n].data += self.update_ewc_parameter*p.grad.data ** 2 / number_data`
					- 其实就是 TD 的 EWC 嘛
		- update 过程
			- 与 SI update过程完全一致
		- 总体上来说是 EWC(TD) 和 SI 方法的结合

	- SCP(Sliced Cramer Preservation)
		- `lll_loss` 计算
			- `_loss = self._precision_matrices[n] * (p - self._state_parameters[n]) ** 2`
				- 前半项是 guard 矩阵
				- ==guard 矩阵更新策略==如下
					- 对每个 batch 的模型输出 `output` 求均值 `mean_vec`，得到该 batch 的平均输出表示
					- 在输出空间随机采样 `L` 个单位方向向量 `vec`，计算随机投影 `scalar = vec · mean_vec`；将这些投影取平均得到 `total_scalar`
					- 对 `total_scalar.backward()`，得到每个参数对这些随机投影的梯度，并使用 `p.grad ** 2 / num_data` 累加到 guard 矩阵，即**参数对输出(选中的众多方向)重要性**
				- 利用 单位随机投影与旧输出矩阵乘能反应旧输出在不同方向的投影，再用投影依次累积梯度(相当于在该方向的影响)，这样相比直接用 旧输出矩阵求梯度计算量会小很多
		- 无update过程

- 总结一下
	- EWC - MAS - SCP 比较像
		- EWC 注重分析 参数与loss
		- MAS 和 SCP 注重分析 参数与输出本身(SCP可以说是MAS的性能改进版)
	- SI
		- SI 注重分析 参数与loss，与 EWC 不同的是 EWC 的 guard 只通过 grad衡量参数对loss的重要性，而 SI 是通过 `grad × parameter change` 近似衡量该参数对实际 loss decrease 的贡献
		- 从某种程度上说 SI 应该是 EWC的更进一步
	- RWalk = EWC(TD) + SI






|操作|改变 Dropout/BN 行为|是否构建计算图|能否 backward|
|---|---|---|---|
|`model.train()`|是，训练模式|是|是|
|`model.eval()`|是，评估模式|是|是|
|`torch.no_grad()`|否|否|否|
|`torch.inference_mode()`|否|否|否|

- `y_detached=tensor.detach().clone()`
	-  `detach()`：断开与原计算图的梯度关联
	- `clone()`：复制一份独立数据，避免和原 Tensor 共享底层存储
	- 因此 `y_detached` 可以近似看作一个**用当前数值重新创建出来的新 Tensor**

- `requires_grad=False`：从一开始就不要求追踪它的梯度，它被视作常量 Tensor


- 在 Tensor 的计算中，一定要有==计算图意识==，考虑该行为是否应该在当前计算图中，一些常见的切断计算图的情形
	- Tensor切断之前的计算图，从 autograd 视角，可以近似理解为“拿当前数值重新作为一个新的起点” ---- `y_detached=y.detach().clone()`
	- 完全不想涉及计算图时 --- `with torch.no_grad():`
		- 当然可能会有类似 `model.weight.data += tensor` 的操作也是为了规避计算图，但是最好还是采取 `with torch.no_grad():`

- Loss 分析
	- **这个 loss 的数值在衡量什么？**
	- **它对哪个中间变量或参数求导？**
	- **梯度方向是否符合设计目标？**
	- **误差变大/变小时，梯度强度怎么变化？**
	- **有没有饱和、爆炸、梯度消失或异常点？**
	- **和其他 loss 组合后，梯度是否冲突或失衡？**
